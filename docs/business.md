# 経営（宝石商社）— 実装の手引き

次に実装する AI エージェント向け。CLAUDE.md を読んだあとに最後まで読むこと。
ユーザーと決めた仕様（2026-10-13）と、任された細部をこちらで決めたものをまとめてある。
実装が済んだら、今の仕様として CLAUDE.md の §3（ファイル表）・§4（ラン外の要素）に移し、この文書は消す（CLAUDE.md §8 の参照も消す）。

## 1. ユーザーが決めたこと（動かさない）

- 入るのはコインだけ。ステータスの強化は一切なし（computeStats・練度・百獣などに触れない）。
- ランとは連動しない放置系。時間で採掘・研磨・販売が進む。
- 規模は「これ一本で別ゲー」くらいの本格派。工数が多いのは承知の上。フェーズに分けて出す（§10）。
- 通貨：経営の中は独自の資金（$）で回す。コイン → $ の「出資」（一方通行）と、$ → コインの「配当」（1 日の上限つき）でつなぐ。
- 置き場所：画面の下のメニューに 6 つ目「経営」を足す。中はハブのカード方式にしない。1 画面の世界地図をスクロールして、拠点を押して操作する。
- 地名は実在のものを使う。
- 手間のかけ方などの細部は任された（この文書で決めた。§11 に一覧）。

## 2. 元ネタ：本物の宝石の流れ

| 段階 | 本物 | ゲームでは |
|---|---|---|
| 採掘 | 国から採掘権を得て掘る。ダイヤは大企業の大規模鉱山、色石は 8 割ほどが小規模な手掘り。産地で値段が大きく変わる | 鉱区の開拓権を買う。設備で産出が増える。埋蔵量があり、尽きると枯れる |
| 原石の取引 | ダイヤはボツワナのハボローネで年 10 回ほどの販売会（サイト）。箱単位で中身は選べない。色石は産地の市場や入札 | 卸で原石のまま売れる。ハボローネの「サイト」で中身の見えない原石の箱を買える |
| 研磨 | ダイヤはインドのスーラトが世界の大半。色石はタイ・スリランカ・インドのジャイプル。高級品はアントワープ、精密な色石はドイツのイーダー・オーバーシュタイン。磨くと重さは半分以下になることが多い | 工場ごとに処理量・腕前（歩留まりと品質）・得意な石・手間賃が違う。磨き方の方針を選ぶ |
| 処理 | ルビー・サファイアの加熱、エメラルドの含浸が一般的。非処理は高く売れる | 処理すると品質が上がりやすいが「非処理」の上乗せを失う |
| 鑑定 | 鑑定機関の鑑定書と産地証明で値が上がる（ミャンマーのルビー、コロンビアのエメラルドなど） | 鑑定所で鑑定書を付けると値が上がる。有名産地は産地証明でさらに上がる |
| 卸 | 取引所や卸業者。売れた分だけ払う委託取引もある | 取引所で相場の 6 割前後ですぐ売れる |
| 小売 | 宝飾店・ブランド・百貨店・ネット。特別な石はジュネーブなどのオークション | 直営店（高く売れるが 1 時間に売れる数に上限）、オークション（良い石だけ・値に幅）、注文（期限までに納めると高い報酬） |
| 値段 | 希少さ・品質・産地・処理の有無・流行。合成ダイヤで天然の値が下がっている | 宝石ごとの相場が時間で動き、流行と出来事で上下する |

企業名・ブランド名は出さない。施設は地名で呼ぶ（「ジュネーブのオークション」「カールスバッドの鑑定所」）。

## 3. 全体の流れ

```
鉱区（原石が倉庫にたまる）
  → 出荷（距離に応じた時間。地図に線と点で出す）
  → 工場（順番に研磨。方針・処理）→ 本社の在庫（磨いた石）
  → （鑑定所）→ 売る：取引所（卸）／直営店／オークション／注文
原石のまま取引所で売ることもできる（安い・早い）
```

- プレイヤーが決めること：どの鉱区を買うか、どの工場で磨くか（距離・得意・手間賃・腕前）、磨き方（歩留まり重視／輝き重視）、処理するか、鑑定するか、どこでいつ売るか（相場と流行）、人を雇ってどこまで自動にするか。
- 序盤は手で回す（回収・出荷・売却を押す）。会社が育つと人を雇えて自動になり、放置で回る（§6.6）。
- 会社のランク（総資産で決まる）で、行ける地域・施設・配当の上限・放置の上限が広がる（§7.2）。

## 4. 画面

### 4.1 下のメニュー
- menu.js の `NAV` に `{ id: 'biz', jp: '経営', en: 'BUSINESS' }` を「宝石」と「記録」の間に足す。`#mnav` の `grid-template-columns` を 6 列に。SE（375px）で文字が見切れないか wrap.js で確かめる。
- アイコンはコードで描く（地球と航路の弧。render.js に `bizIcon`）。
- 印（バッジ）：配当を受け取れる／倉庫が満杯の鉱区がある／新しい注文がある、のどれか。refreshNav から biz.js の要約（`bizAlerts`）を呼ぶ。
- 経営の画面は `data-nav="biz"`。ハブ（HUBS）は使わず、メニューの「経営」は直接 showBiz() を開く。

### 4.2 地図の画面（showBiz）
- 上の帯：`BUSINESS ／ 経営`、資金（$）、配当（今日の残り。押すと本社のシート）、コイン。
- 地図：横に長い世界地図（正距円筒図法。北緯 75°〜南緯 50°）。ネイティブのスクロールで動かす（`overflow: auto` の箱の中に大きな地図。iOS の慣性スクロールがそのまま効く）。拡大は 2 段（＋／− のボタンで地図の幅を変える。拠点は % で置くのでそのまま付いてくる）。開いたときは本社（東京）か、前に見ていた位置（`save.biz.view`）。
- 陸地は SVG。大陸を手で単純化した経緯度の多角形（各 20〜60 点、js/biz-map.js）にして、点の模様（pattern）で塗る。海は黒に近い紺、経緯線をうっすら。大きいキャンバスは作らない（iOS のメモリのため。SVG と DOM で描く）。
- 拠点：地名ごとに 1 つのピン。1 つの地名に施設が複数あってよい（例：アントワープ＝取引所＋工場）。ピンの見た目：
  - 種類のアイコン（つるはし＝鉱区、歯車＝工場、天秤＝取引所、虫めがね＝鑑定所、木槌＝オークション、袋＝店、星＝本社）。既存の pickaxeIcon・gavelIcon は使い回す。
  - 状態：未所有は暗く値段を小さく、所有は宝石の色で光る、作業中はゆっくり脈打つ、倉庫が満杯は赤い印。ランクが足りない地名は鍵（名前は出してよい）。
  - 拡大したときだけ地名の文字を出す。
- 輸送中の荷は、拠点どうしを結ぶ弧（SVG の path）の上を点が進む。画面を開いている間だけ rAF で動かす（地図の画面を離れたら止める）。
- 拠点を押すと、下から「シート」が上がる（地図の上に重なる。メニューの上、`.screen.dim` は使わない）。シートの外か取っ手を押すと閉じる。シートの中身は施設ごと（§4.3）。施設が複数ある地名は、シートの中で切り替える。
- 右下に小さな丸ボタン：本社（本社のシート）・相場（相場のシート）。

### 4.3 シートの中身（どれも文言は機能に必要なものだけ）
- 鉱区：地名・国、出る宝石（gemIcon と割合）、埋蔵量のバー、産出（ct/時）、倉庫（今/上限）のバー。ボタン：開拓権を買う／回収して出荷（工場を選ぶ）／原石のまま売る（いちばん高い取引所の値を出す）／設備を強化／倉庫を広げる／鉱山長を雇う。
- 工場：待っている原石（ct）、処理量（ct/時）、腕前、得意な石、手間賃（$/ct）、方針（歩留まり重視／輝き重視）、処理（する／しない）。ボタン：買う／強化／職人を増やす／工場長を雇う（出来上がりの行き先：在庫・取引所・鑑定所）。
- 取引所：在庫の宝石ごとの買い取り値（相場×この取引所の掛け率）と「売る」。原石も売れる。
- 鑑定所：鑑定書の費用と日数（実時間の分）、在庫から選んで出す。
- 直営店：棚（並べる石）、1 時間に売れる数、掛け率、街の好み。ボタン：出店／強化／店長を雇う。
- オークション：次の開催までの時間、出品できる石（品質 S 以上）、出品。結果は次に開いたときに出す。
- 注文：依頼主（「パリの老舗ジュエラー」など地名＋業種）、条件（宝石・品質・個数）、期限、報酬。受ける／納める。
- 本社：資金、総資産、ランクと次のランクまで、出資（コイン → $。量を選ぶ）、配当（今日の上限と受け取り済み、受け取る）、在庫の一覧（磨いた石・原石）、放置の上限、記録（累計の売上・配当）。
- 相場：宝石ごとの相場（基準からの %・上がり下がりの矢印）、流行の印、出来事の一覧（例「モゴックで大雨：ルビー +25%（あと 9 時間）」）。

### 4.4 見た目
- 黒ベース。宝石の色の光るピンと航路が映えるように。地図は控えめな明るさ（文字と光が主役）。
- 品質の色は既存の GRADES（atelier.js。C 緑・B 青・A 紫・S 金・SS 虹）と atelier-ui.js の gradeBadge を使い回す。
- 金額の表記：$ は 1,234 → 12.3K → 4.56M。コインは既存の coinIcon。
- 画面の文言は短く。説明文・飾りの文句は入れない（CLAUDE.md §2）。

### 5.3 施設の数値（最初の目安。§8 の sim で合わせる）
- 鉱区：開拓権の値段、産出（原石 ct/時）、品質の分布（C/B/A/S/SS）、埋蔵量（ct）、倉庫の上限（ct）。設備の段階：手掘り → 小型機械 → 重機 → 大規模（産出 ×1 / ×2.2 / ×4.5 / ×9。値段は 1 段ごとに大きく上がる）。設備が良いほど品質の分布が少し上に寄る。埋蔵量が尽きたら閉山（拠点は残り「枯渇」と出す）。探鉱（$ と時間）で埋蔵量を足せる。
- 工場：処理量（原石 ct/時）、腕前（歩留まりの倍率と品質の上振れ）、得意な石（歩留まり・品質に上乗せ）、手間賃（$/ct。研磨したときに資金から引く。資金が足りなければ止まる）。強化で処理量、職人で腕前。
- 輸送：時間は距離に比例（地球の表面の距離 km ÷ 2000 km/時 を目安に、2〜30 分に収める）。運賃は ct あたり少し。
- 取引所の掛け率：0.5〜0.7（得意な石は上）。原石の買い取りは、その原石を標準の腕で磨いた場合の値の 2 割ほど。
- 直営店：掛け率 1.3〜1.8、1 時間に売れる数（強化で増える）、棚の数。好みの石は売れやすく高い。
- オークション：4 時間ごと。品質 S 以上。落札値は 相場 ×（1.3〜3.0。SS と鑑定書・産地証明で上に寄る）。
- サイト：8 時間ごとに 1 箱。値段は固定、中身（ダイヤの原石の量と品質）はランダム。期待値は値段より少し上だが、腕の良い工場で磨かないと損をしやすい。
- 注文：3 時間ごとに最大 3 件。報酬は相場の 1.5〜2 倍。期限切れは何も起きない（罰なし）。

## 6. 仕組み（js/biz.js。DOM・save.js を読まない純粋な関数にして、Node のテストからも動かせるようにする）

### 6.1 状態（save.biz）
```js
save.biz = {
  v: 1,                     // 形を変えたら上げて migrateSave で直す
  cash, last,               // 資金（$）と最後に計算した時刻（Date.now()）
  rng,                      // 乱数の種（追いつき計算の結果を開き直しで変えないため）
  rank,                     // 会社のランク（総資産から決まるが、下がらない）
  view: { x, y, zoom },     // 地図の位置
  mines: { [siteId]: { lv, reserve, store: { 'gem|grade': ct }, boss, to } },     // to：鉱山長の出荷先の工場
  factories: { [siteId]: { lv, crew, policy, treat, queue: [{ gem, grade, origin, ct }], boss, out } },
  ships: [{ from, to, items, arrive }],
  rough: { 'gem|grade|origin': ct },                       // 本社の原石（サイトの箱など）
  stock: { 'gem|grade|origin|treat|cert': { n, ct } },     // 磨いた石の在庫
  labs: [{ site, key, n, ct, done }],
  shops: { [siteId]: { lv, shelf: { key: n }, boss } },
  market: { idx: { gem: 1 }, trend: { gem: x }, events: [], next },
  contracts: [], auctions: { [siteId]: { next, lots: [] } }, sight: { next },
  div: { day, paid },       // 配当：日付（ui.js の todayStr と同じ形）と受け取ったコイン
  invested, earned, divTotal, // 記録
};
```
- 最初に経営を開いたときに作る（元手の資金を渡し、本社だけ持った状態）。save.js の defaults には `biz: null` だけ足す。

### 6.2 追いつき計算（catchUp(state, now)）
- 経営の画面・メニューの印・本社のシートを開くたびに呼ぶ。ラン中は呼ばない（重さのため）。
- `now - last` を 60 秒刻みで進める。上限は放置の上限（最初 8 時間、本社の強化で 24 時間まで）。上限を超えた分は捨てる。時計が戻っていたら last を now にするだけ。
- 1 刻みの順番：鉱区の産出（倉庫が満杯なら止まる）→ 鉱山長の自動出荷 → 荷の到着 → 工場の研磨（手間賃を払えるだけ）→ 工場長の行き先へ → 鑑定の完了 → 直営店の販売 → 相場の更新（1 時間ごと）→ 流行・出来事（1 日ごと・ランダム）→ 注文・オークション・サイトの時刻。
- 乱数は state.rng の種から（mulberry32 など）。
- 地図の画面を開いている間は 1 秒ごとに catchUp して表示を更新する（地図の作り直しはせず、数字とバーと点だけ書き換える）。

### 6.3 研磨の計算
- 原石 ct → 磨いた石：個数 = ct × 歩留まり ÷ 1 個の大きさの目安。歩留まり = 宝石の基準 × 工場の腕前 × 得意の上乗せ ×（歩留まり重視なら ×1.15、輝き重視なら ×0.85）。
- 品質：原石の品質から、工場の腕前と方針（輝き重視なら上振れしやすい）で 0〜1 段上がることがある。処理するなら §5.1 の通り。
- 在庫は同じ種類（宝石・品質・産地・処理・鑑定書）をまとめて `{ n, ct }` で持つ（1 個ずつ持たない）。

### 6.4 値段
`値 = 基準単価 × GRADE_MUL × (ct/n)^0.3 × ct × 相場 × 処理 × 鑑定書（×産地証明）× 売り先の掛け率`
- 相場：宝石ごとに 0.6〜1.8。1 時間ごとに少し上下し、1 に戻ろうとする。流行（1 日ごとに 2 種が上がり 1 種が下がる）と出来事（例：「モゴックで大雨」ルビー +25% 12 時間）を足す。
- 同じ宝石を一度にたくさん卸すと、その宝石の相場が少し下がる（時間で戻る）。1 種だけを売り続けるより、散らすほうが得になるように。

### 6.5 配当と出資
- 配当の 1 日の上限 = max(300, 1 ランの平均コイン) × ランクの係数（0.3 → 2.0）。1 ランの平均コイン = `save.stats.runCoins / save.stats.runs`（settleRun で runCoins にランで得たコインを足す。新しく作る記録）。
- 換算はランクごとに決める（$ の価値はランクが上がるほど下がる）。目安は「そのランクの標準的な時給で、1 日の上限におよそ 8 時間で届く」。
- 出資：コイン → $。換算は配当の 1/3 の有利さにする（出資したコインをそのまま配当で戻すと目減りする。行って帰るだけで増える抜け道を作らない）。
- 日付は ui.js の todayStr と同じ（util.js に移して共用する）。

### 6.6 人を雇う（自動化）
- 鉱山長（鉱区ごと）：倉庫が半分を超えたら、決めた工場へ自動で出荷。
- 工場長（工場ごと）：出来上がりの行き先を決める（在庫にためる／決めた取引所で売る／品質 S 以上は鑑定所へ）。
- 店長（店ごと）：棚が空いたら在庫から好みの石を並べる。
- 雇うのは $。ランク 2 から。全部雇えば放置だけで回る。

### 6.7 会社のランク
総資産 = 資金 + 施設に払った額の半分 + 在庫を相場で卸した場合の値。ランクは一度上がったら下がらない。
1 露店 → 2 宝石店 → 3 宝石商 → 4 卸問屋 → 5 宝石商社 → 6 国際商社 → 7 宝石財閥。
ランクで開くもの：行ける地名（§5.2 のラン）、人を雇う（2）、直営店（2）、鑑定所（3）、オークション（4）、サイト（5）、放置の上限、配当の係数。

## 8. バランスの目安とテスト

- 目安：最初の鉱区と工場は 15〜30 分で元が取れる。ランク 2〜3 の施設は数時間。ダイヤの鉱区は 1〜2 日。値段は 1 段ごとに 1.6〜2.2 倍。
- 配当：ふつうに遊ぶ人（1 日に数回開く）が、ランク 3 ごろから毎日上限に届く。上限はランク 7 でも 1 日にランの 2 回分程度にとどめる（本編のコイン稼ぎを置き換えない）。

## 9. 地図の作り方の注意

- 正距円筒：x = (経度 + 180) / 360 × 幅、y = (75 − 緯度) / 125 × 高さ。拠点の位置は % で持つ。
- 大陸の多角形は「形がわかる程度」でよい（ユーラシア・アフリカ・北米・南米・オーストラリア・南極は省略・グリーンランド・日本・マダガスカル・スリランカ・イギリス・ニュージーランド・インドネシアの大きい島）。地名のピンが陸地の上に乗るように、ピンの周りだけは形を合わせる。
- 近い地名（スイスの 2 か所、アントワープとイーダー・オーバーシュタインなど）は、縮小時は 1 つにまとめた印にして、拡大で分ける。
- スクロールの箱の中で拠点のボタンを押せるように（ドラッグとタップを取り違えないよう、少しでも動いたらタップにしない）。
